## Summary

The governance contract currently uses a hardcoded weight of `1` per voter. This issue wires up the real cross-contract call to `token-weight::get_weight()` so voting power reflects actual token balances.

## Context

- `contracts/governance/src/voting.rs` — `cast_vote()` has a `// TODO (Phase 2)` comment where the weight call belongs.
- `contracts/token-weight/src/lib.rs` — `get_weight(voter)` is already implemented and returns `token.balance(voter)`.

## What to implement

In `contracts/governance/Cargo.toml`, add the token-weight crate as a dev-dependency:

```toml
[dev-dependencies]
token-weight = { path = "../token-weight" }
```

In `contracts/governance/src/voting.rs`, replace:

```rust
// TODO (Phase 2): replace with real token-weight cross-contract call.
let weight: i128 = 1;
```

with a cross-contract call using the client generated by `soroban-sdk`:

```rust
use token_weight::TokenWeightContractClient;

let weight_addr = storage::weight_contract(env);
let weight_client = TokenWeightContractClient::new(env, &weight_addr);
let weight = weight_client.get_weight(voter);
```

## Acceptance criteria

- [ ] `cast_vote` calls `token-weight::get_weight(voter)` instead of using `weight = 1`.
- [ ] A new test in `governance/src/test.rs` deploys a real `TokenWeightContract`, mints different balances to two voters, has both vote `For`, and asserts `proposal.votes_for` equals the sum of their balances.
- [ ] `cargo test --all` passes.
- [ ] `cargo clippy --all-targets -- -D warnings` passes.
